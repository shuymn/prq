# Screens and states

Every screen and state in [docs/ui.md](../docs/ui.md), the Pencil frame that shows it, and what the frame must make
visible. A frame named here is a root frame of [prq.pen](prq.pen), below the component sections: one column per screen,
in the order of the sections below, with the frames in table order. Desktop frames are 1440 wide and at least 900 tall,
panel frames `size.panel` (360) wide and at least 800 tall. To the right of each frame a `Note` instance named
`Note / <frame>` lists the state IDs the frame shows and the guides it relies on. Some frames show several states at once
(the list shows every problem label); the table says which. The `Brand` frame, which holds the product mark, is a
component section ([components.md](components.md#brand)), not a screen.

The state ID is stable: code (#7) uses it for the gallery and for tests that pick a state.

## 2. PR detail

Desktop layout: header, then a body `size.detail` wide, centered on the page, with a main column (summary pinned above
the conversation, composer at the bottom) and a right rail (a head with the toggle that collapses it, the versions,
then the jobs, where done jobs collapse into one "N done" line). Collapsed, the rail keeps only its toggle and the main
column takes the width; the toggle carries a danger dot while a job has failed or is possibly stalled. States that
affect content show next to it: at the summary (its heading, or a Notice above its body), under an answer, or in the
composer; the rail only lists them again.

The expanded rail is in the other detail frames                                                  |

## 3. Agent pool

A popover opened from the pool status in the header. Each frame shows the PR list with the popover open.

| State ID           | Frame                            | Must show                                                                                         |
| ------------------ | -------------------------------- | ------------------------------------------------------------------------------------------------- |
| `pool.local`       | Agent pool / Local agent present | Which agent IDs are present, last seen, waiting or holding a job; cloud available; jobs in flight |
| `pool.cloud-only`  | Agent pool / No local agent      | That new PRs go to cloud and existing local sessions wait                                         |
| `pool.unavailable` | Agent pool / Unavailable         | The status could not be read: the header button in its unavailable form and the popover saying so |
| `pool.loading`     | Agent pool / Loading             | The header button while the status is being read; the popover is closed                           |

| -------------------------- | ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `settings.default`         | Settings / Default                   | Header with the settings button marked as the current page (fill and an `accent.fg` underline); both prompts with text; the skills list with source, ref, pinned SHA, allowed tools; "Add skill" in the Skills heading                                                                                          |

| `settings.register-failed` | Settings / Register failed           | The "Add skill" dialog with the reason: the link is not a GitHub link to a `SKILL.md`, the repository or ref was not found, no `SKILL.md`, invalid frontmatter, or the name already registered                                                                                                                  |
| `settings.saving`          | Settings / Saving and saved          | One prompt saving, the other saved                                                                                                                                                                                                                                                                              |
| `settings.save-failed`     | Settings / Save failed               | A prompt whose save failed, with a way to retry                                                                                                                                                                                                                                                                 |
| `settings.update`          | Settings / Update review             | The ref field that Update opens on a skill row (prefilled with the current ref, then "Review update"), holding the new ref, and over the page the review dialog: old → new ref and SHA and the change in allowed tools; Apply, which pins exactly the reviewed SHA, and Cancel, which leaves the skill as it is |

Every dialog sits on a backdrop that covers its frame.

## 5. Extension side panel

The PR detail at 360px: compact header, the summary in a disclosure whose heading is the version menu (SHA and time
once), the conversation and the composer. The pool status line and job lines appear only where they explain content
that is blocked; a failure shows inline with Retry. The panel frames also check that long titles, metadata and code
blocks fit.

| State ID                  | Frame                             | Must show                                                                                                                                                                                                                                                                       |
| ------------------------- | --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `panel.default`           | Panel / Default                   | All panel elements with a long PR title, an answer with a code block, and answer metadata; no pool line and no job line                                                                                                                                                         |
| `panel.version-menu`      | Panel / Version menu open         | The version menu open from the summary heading, kept inside the panel: versions by SHA with status, the selected one checked                                                                                                                                                    |
| `panel.streaming`         | Panel / Streaming                 | An answer arriving, with its running line: "cloud" and when the turn started, no Retry                                                                                                                                                                                          |
| `panel.summary-streaming` | Panel / Summary streaming         | The running version picked in the version menu: its partial text arriving with its running line ("cloud" and when the turn started, no Retry) and the model without a token count, and the composer saying questions are answered at the latest analyzed SHA                    |
| `panel.waiting-agent`     | Panel / Waiting for a local agent | The pool status line (cloud only) that explains the wait, and the waiting question with its one line, wrapped                                                                                                                                                                   |
| `panel.failed`            | Panel / Failed                    | The incomplete answer with the reason and Retry under it, and the SHA it was answered at                                                                                                                                                                                        |
| `panel.disconnected`      | Panel / Disconnected              | Banner and the disabled composer with its reason                                                                                                                                                                                                                                |
| `panel.reconnect-failed`  | Panel / Reconnect failed          | The failed banner with Reload and the disabled composer with its reason                                                                                                                                                                                                         |
| `panel.unavailable`       | Panel / Status unavailable        | The status line when the pool status cannot be read                                                                                                                                                                                                                             |
| `panel.new-version`       | Panel / New version               | The new version Notice with Reload at the top of the panel, above the header; nothing else changes                                                                                                                                                                              |
| `panel.send-failed`       | Panel / Send failed               | Settled after no history read following the send completed: the question marked "Couldn't confirm it was sent" with Try again and Discard wrapped under it; Send off with the hint; the new version Notice above the header ending with "Reloading loses your unsent question." |
