# Component inventory

Every reusable element of the web UI, as it exists in the Pencil document [prq.pen](prq.pen) and as it will exist in
code. Pencil has no variants, so each combination of a component's props is its own Pencil component, named after the
React component followed by the prop values; the props keep their names and values in code. Screens are built only
from these components and the tokens in [tokens.json](tokens.json); an element or value that is missing is added here
or to the tokens first. How the pieces fit together is in [README.md](README.md).

The components sit at the top of the canvas, one root frame per section below (`Foundations`, `Status and labels`, ...)
with a title and the components in rows.

Columns:

- **Name ↔ props:** the Pencil name pattern, then each prop in the pattern and its values. In code, each `<prop>` is a
  prop of the same name. Text and repeated content are not part of the name: an instance overrides the named text node
  (for example `label`, `title`, `sha`) and turns off an optional node with `enabled: false`. A component without
  props is named like the React component.
- **Tokens:** the semantic tokens the component binds (palette tokens and the `space.*` scale are never bound directly;
  spacing is named by its role, `gap.*` between siblings and `inset.*` inside a container), by token path. In
  Pencil a token is the variable named like its CSS custom property (`color.fg.muted` → `$color-fg-muted`, typography
  split into `text-body-font-size` and so on).
- **Guides:** the `modern-web-guidance` guide IDs the design relies on. The implementation (#7) retrieves them again.
- **Panel:** **yes** when the component must work in the extension side panel (360px wide).

Pencil keeps variable bindings on fills, strokes, stroke widths, radii, padding, gaps, text properties and shadows, but
drops them on `width` and `height`. A fixed size that a token covers is therefore the token's value with the token
recorded in the node's `context`, `tokens width=size.icon height=size.icon`; [pencil-audit.js](pencil-audit.js) checks
that the number matches the variable. (`context` rather than `metadata`, because `execute` can set `metadata` only when
it inserts a node.)

Icons are GitHub Octicons 19 (MIT), 16px, drawn as the Octicon's SVG path. A component that shows an icon holds an
`Icon/<name>` instance named `icon` (or after its role, such as `chevron`); a screen swaps it by replacing that node
with another `Icon/<name>` instance.

An icon is centred on the first line of the text it leads. Where the text can take more than one line (Status, Notice,
ConnectionBanner, the PoolPopover agent rows, Message questions, field errors, the Composer's disabled reason, the
PromptEditor failure, the SkillReview source and file rows), the row aligns to the top and the icon sits in a `lead`
frame one line of that text high, centred in it: the frame holds the icon and `strut`, a zero-width text in the first
line's text style (`text.body-strong` gives 14 × 1.5 = 21, `text.small` 12 × 1.5 = 18), because a line height is not a
size token. In code the lead is `height: 1lh` in that text style with `align-items: center`. A row whose text stays on
one line centres the icon with `align-items: center`; Disclosure's chevron sits in a `size.control.sm` lead next to a
summary row of the same height, which centres both.

Button looks: primary and danger are filled (`accent.emphasis`, `danger.emphasis`; hover the `-hover` token) with
`fg.on-emphasis`; secondary is `bg.subtle` with a `border.default` border and `fg.default` (hover `bg.muted`); invisible
has no fill and `fg.default` (hover `bg.muted`). Disabled is `bg.subtle` + `border.default` with `fg.disabled`
(invisible: `fg.disabled` only). Busy puts a Spinner (`spinner`) before the label, its arc in the label color. The text
node is `label`.

Control size per context (README "One control size per context"); a screen switches an instance to the component of
the right size and never resizes it:

- **md:** AppHeader (PoolStatus `form=button`, the settings IconButton invisible); the PR list toolbar ("Needs
  attention · N" Button secondary, RepoFilter, SegmentedControl, whose track is md around sm segments); PrHeader in both
  densities and the rail head ("Open on GitHub" Button secondary or IconButton invisible, the compact header's back
  control, the rail toggle); forms, dialog footers, Composer and the Settings page ("Send", "Save prompt", "Add skill",
  "Review update" and "Cancel" in the ref form, dialog actions, EmptyState actions).
- **sm:** rows (JobRow "Retry", SkillRow "Update" and "Remove"); inline notices and status lines (Notice and
  ConnectionBanner actions, the "Retry" of Summary `progress` and of the running lines, Message `failure`); CodeBlock
  copy; the VersionMenu trigger in the Summary heading and in the panel's Disclosure row.
- **Menu and list items** that are themselves the target (VersionItem in the rail and in the VersionMenu, RepoMenuItem
  in the RepoMenu) are `size.control.md` tall, like any other item a pointer has to hit in a list.

The focus state draws the outline the code draws with `:focus-visible`: the button sits in a `focus-offset` frame inside
a ring frame (the component root) with a `border.focus` inner stroke of `border-width.thick` and `radius.lg`. The ring
frame's padding is the ring width (`border-width.thick`) and the `focus-offset` frame's padding is the gap
(`focus.offset`, 2px). The focus component is therefore 8px larger than the button; in code the outline takes no space.

The selected segment of SegmentedControl carries a bottom indicator, a one-side stroke of `border-width.thick` in
`accent.fg` (5.59:1 against `bg.subtle`), because its `bg.muted` fill alone is 1.16:1 and WCAG 1.4.11 asks for 3:1.

IconButton invisible md is the settings button at the end of AppHeader (gear, named "Settings") and the rail toggle in
the PR detail rail head (named "Jobs and versions" in both states, `aria-expanded` saying whether the rail shows them;
sidebar-collapse in the expanded rail, sidebar-expand in the collapsed rail), both with the glyph in `fg.muted`. On the Settings page the settings button is marked as the
current page (`aria-current="page"`) with the `bg.muted` fill and, because that fill alone is 1.16:1 against
`bg.subtle`, a bottom indicator of `border-width.thick` in `accent.fg` like the selected segment of SegmentedControl.
While a job has failed or is possibly stalled, the collapsed rail's toggle carries an `Icon/dot-fill` in `danger.fg` at
its top-right corner, and its description (`aria-description`, not its name) says "A job needs attention"; in Pencil the
screen places the two instances in a `rail-toggle` frame without layout. In the PR list toolbar, Button secondary md is the "Needs attention
· N" filter: a toggle button (`aria-pressed`) that keeps the rows with a problem the host can act on (failed,
possibly stalled, waiting for a local agent), its label carrying their count; "New push not summarized" does not count.
It is shown only while N is above zero.

Notice is a row of the icon (in its `lead` slot) and a column with `title`, `text` and `actions`, so the text lines up
under the title by layout rather than by an indent. Skeleton has no size tokens of its own: the component borrows `size.icon` (line height),
`size.header` (block height) and `size.popover` (width) as defaults, and screens size each instance to the content it
stands in for.

ConnectionBanner and the new version notice sit first in the page content (the main column on desktop, above the
PrHeader in the panel) and fill its width. While the WebSocket reconnects the banner is `reconnecting`: "Reconnecting…
Showing the last known content." When reconnecting keeps failing it becomes `failed`: "Can't reconnect. Try reloading
the page." with Button secondary sm "Reload", which reloads the page; the last known content stays, and reconnecting
goes on in the background. The UI cannot tell why the attempts fail (an expired Access session, which a WebSocket
cannot follow to the sign-in redirect, see [Caching](../docs/design.md#caching); or the network or the server being
down), so the copy names no cause and promises no recovery. A reload reconnects too, so there is no separate retry.
The Composer's disabled reason follows the banner ("Reconnecting. You can send once the connection is back." /
"Disconnected. You can send once the connection is back."). After a deploy, a tab whose build version differs from the
server's shows Notice info: "A new version is available", "This tab still runs the previous version. Reload to update
it." and Button secondary sm "Reload". A lazily loaded asset that fails to load does not prove a newer version exists,
so without a confirmed version mismatch the same Notice says "Couldn't load part of this page." and "Try reloading."
with the same "Reload". It is inline rather than a toast, has no dismiss, blocks nothing, and looks the same on every
page. From Send until stored history holds the question or the host discards it, reloading loses the question, so on
every page (also after leaving its pull request) each Reload notice (the failed ConnectionBanner, the new version
Notice, the asset Notice and the settings' display failure below) ends its text with "Reloading loses your unsent
question."

Reads that fail or come back empty use these components with this copy:

- **Load failure:** a first read failed, so there is nothing to show. Notice danger in the content's place with
  "Couldn't load pull requests" (the PR list's table), "Couldn't load the summary and conversation" (the PR detail's
  history, in place of the Summary and the conversation), "Couldn't load repositories" (the RepoFilter menu, in place
  of its items) or "Couldn't load settings" (the settings page, in place of its prompts and skills) as the title, its
  `text` off, and Button secondary sm "Try again", which reads again. Until the first read completes, Skeleton holds the
  places of what it reads (the settings' editors and skill list).
- **Refresh failure:** a later read failed. The same Notice danger sits above the content it failed to refresh, which
  stays as last read: "Couldn't refresh pull requests", "Couldn't refresh the summary and conversation" or "Couldn't
  refresh settings", "Showing what was loaded before." and "Try again".
- **Display failure:** the settings page failed as it showed what it read. Notice danger in the page's place with
  "Couldn't show settings", "Reload the page to try again." and Button secondary sm "Reload", which reloads the page;
  the header and the other pages keep working.
- **No rows for a filter:** EmptyState in the table's place, the toolbar kept, no actions. Open on all repositories:
  "No open pull requests", "Choose All to see closed and merged ones."; a repository chosen: "No pull requests match
  these filters", "Choose another repository, or All to include closed and merged ones."; Needs attention: "Nothing
  needs attention", "Turn off Needs attention to see every pull request." The onboarding copy of `list.empty` shows only
  when the unfiltered ledger is known empty (a read without filters returned no rows).
- **No page at the address:** EmptyState with `alert`: "Page not found", "There is no page at this address." and Button
  secondary md "Go to pull requests".
- **Unknown pull request:** a PR detail whose session has no details, no jobs and no messages. EmptyState with
  `git-pull-request`: "Unknown pull request", "prq has nothing for shuymn/prq#99. A pull request appears once the GitHub
  App receives a webhook for it." and "Go to pull requests".
- **Next page:** while the PR list loads its next page, Skeleton `line` rows in the row's columns and height (as in
  `list.loading`) follow the last row.

A frame that puts a component inside a Disclosure (the Summary in the panel) replaces the instance's `content` node
with that component's instance (a `descendants` entry with `type`). In code the content is the Disclosure's children.
In the panel the summary row is "Summary" (the `label` set to `text.heading`, the level of the desktop Summary
title) followed by the version menu: the frame replaces the Disclosure's `meta` with
a VersionMenu `open=false` instance, so the SHA and time appear once. In code the menu button sits next to `<summary>`
in the same row, not inside it, since a button inside `<summary>` would toggle the disclosure. The Summary inside the
Disclosure turns off its `header` (ready) or its `title` and `version` (streaming, which keeps the running Status).

In the PR detail rail, done jobs collapse into one Disclosure `open=false` whose `label` is the count ("2 done") and
whose `meta` is off; the jobs that are waiting, running, stalled or failed stay listed above it.

An editable field at rest (TextField, TextArea and with it PromptEditor, Composer) draws its boundary in `border.strong`
(6.23:1 against `bg.canvas`) to meet WCAG 1.4.11; `border.default` (1.92:1) stays on cards, rows, dividers and disabled
fields.

Adding a skill starts from "Add skill" (Button secondary md) in the Skills heading, which opens SkillRegisterForm as a
dialog; "Review skill" resolves the link and replaces it with the SkillReview `mode=register` dialog. Updating a skill
takes a new ref: "Update" opens the ref field with the current ref, "Review update" resolves it and fetches the skill,
and the SkillReview `mode=update` dialog shows the old and new ref and SHA and the change in allowed tools. "Apply
update to …" pins exactly the reviewed SHA; "Cancel" leaves the skill as it is. Every dialog sits on a
`bg.backdrop` backdrop that covers the page; Escape and "Cancel" close it, a click outside does not, and focus returns
to the control that opened it.

Errors take these slots. A failed registration preview is SkillRegisterForm `failed`. A failed update preview is the Ref
field's error: "No branch, tag or commit named v3 in shuymn/kopje.", "The SKILL.md at v3 is named review-lite, not
review." or "Couldn't reach the server. Try again." A confirm that fails keeps its dialog open with the `error` Notice:
"Couldn't register the skill" with "A skill named review is already registered. Remove it first, or cancel." (another
skill of that name) or "Couldn't reach the server. Try again."; "Couldn't apply the update" with "The skill changed
since this review. Cancel, then choose Review update for a fresh review." or the same server line; "Couldn't remove the
skill" with the server line. An error that repeating cannot fix (the name taken, the skill changed) disables the confirm
(Button primary md disabled), and Cancel returns to the row, where the Ref field keeps its ref; the server line keeps
the confirm, which tries again. A confirm that got no answer, a server error or that conflict shows its error only once
the list read after it lacks the change; a list that holds it closes the dialog as applied. When that read fails as
well, the `error` Notice says "Couldn't confirm the registration", "Couldn't confirm the update" or "Couldn't confirm
the removal" with "Couldn't reach the server to check. Try again." and keeps the confirm, and once the dialog is closed
a Notice attention under any refresh failure, above the prompts, says "Couldn't confirm that review was registered" (or
"was updated to e4f5a6b", "was removed") with "The next read of the list settles it."; the next read that succeeds
removes it.

## Brand

| Component | Name ↔ props                                                                                                             | Tokens                                                                                                                                                                    | Guides                                                                  | Panel |
| --------- | ------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- | ----- |
| BrandMark | `BrandMark/<variant>` — `variant`: brand, face (the size is the instance's; code: `size` in whole multiples of the grid) | brand: `accent.emphasis` (`tile`) + `fg.on-emphasis` (`face`) on a 16px grid (`asset grid=16`); face: the face alone in `accent.fg`, its 12 × 8 cells (`asset grid=12x8`) | icons, accessibility (decorative next to the product name: empty `alt`) | no    |

BrandMark is the product's only mark: the pixel face, drawn on a 16px grid (the face on rows 4–11). `brand` is the face
in `fg.on-emphasis` on a stepped `accent.emphasis` tile: the favicon, the apple-touch icon and the Chrome Web Store
icon, which holds its own on light and dark tab bars. `face` is the face alone in `accent.fg`, the mark before the
product name in the AppHeader: about as heavy as the name, with no bright area, and recognisably the face of the tab's
icon. Pixel art stays crisp only at whole multiples of its grid, so `brand` is 16 × n and `face` 12 × n by 8 × n (24 ×
16 in the header, 2px cells): the components are 1×, and an instance at another size sets its own width and height and
those of its paths (Pencil does not scale a component's children), recording the grid (`asset grid=16`, `asset
grid=12x8`) in each node's `context`. It is also placed on whole pixels: next to a name the mark centres on the name's
cap height, or on its x-height (x-height top to baseline) when the name is lowercase only, rounded to the nearest whole
pixel. The `Brand` frame holds both components and `brand` specimens at 32, 48 and 128px. The icons: `favicon.svg`
(the `brand` drawing, which Chrome draws at every size), `favicon-32.png` and `apple-touch-icon.png` (180: the grid at
11×, 176px, centred on a 180px canvas filled with `accent.emphasis`, since iOS masks the corners itself), written by
`pnpm run icons` in `packages/server` from the code's drawing and the tokens (the PNGs rendered in Chrome). The 16 and
48px rasters are not made: the SVG serves Chrome, the only browser the UI supports. The Chrome Web Store icon, 128
(96px artwork, 6×, in 16px of transparent padding), comes with the extension.
