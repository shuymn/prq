# Decisions

Which libraries and platform features prq uses, and why. The architecture and the rules these choices serve are in
[design.md](design.md); what the prototype checked is in [spikes.md](spikes.md).

The balance: take an established library where writing the code ourselves would only add maintenance (security
primitives, routing, the chat harness), and write our own where the rule is the point (the job state machine, context
compaction, the instruction plane).

## Harness: AIChatAgent over Pi Durable + PiHarness

The harness holds a conversation per pull request, accepts input from server-side events, and keeps running through
deploys. Two candidates fit. In the table, ✕ means the documentation says it cannot be done and "unconfirmed" means the
documentation does not say.

| Need                                            | Pi Durable + PiHarness                                                                                                                                                                                                                                             | AIChatAgent                                                                                                                                                              |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Store and resume a session per PR               | Yes: records, inbox and tasks in the Durable Object's SQLite                                                                                                                                                                                                       | Yes: message persistence                                                                                                                                                 |
| Drive the same session from a server-side event | Yes: `submit`, idempotent by `operationId`                                                                                                                                                                                                                         | Yes: `saveMessages`, from a webhook or schedule                                                                                                                          |
| A question that arrives while a turn runs       | Yes: queued, or `steer` to interrupt                                                                                                                                                                                                                               | Partly: queued; no interruption, only abort                                                                                                                              |
| An LLM used with an API key                     | Partly: Pi's Cloudflare provider goes through AI Gateway. DeepSeek is a Gateway target and Gateway has Custom Providers for other HTTPS APIs, but whether Pi's Cloudflare provider can use them is unconfirmed, and so is connecting through Pi AI's own providers | Yes: any provider that has an AI SDK provider connects directly                                                                                                          |
| Adding tools (web search)                       | Yes: written as Pi tools (pi-schema); MCP unconfirmed                                                                                                                                                                                                              | Yes: `tool()` with valibot schemas; an MCP client exists                                                                                                                 |
| Compaction of a long conversation               | Yes: built in                                                                                                                                                                                                                                                      | ✕ Written by us                                                                                                                                                          |
| Recovery from a mid-run redeploy                | Yes: saved per step                                                                                                                                                                                                                                                | Yes: durable recovery, always on, with a retry limit. It does not guarantee an external side effect happens once, so the commit step is made idempotent by the job rules |
| Stability                                       | Partly: Pi Durable is experimental and PiHarness is beta; raising Pi's minor version cannot be rolled back; a conversation cannot be deleted                                                                                                                       | Partly: no experimental label, which is not a guarantee of stability                                                                                                     |
| Fit with the rest of the repository             | Partly: adds pi-schema and chord (Pi's diff format for screen delivery) next to valibot                                                                                                                                                                            | Yes: valibot, AI SDK and Agents SDK together                                                                                                                             |

**Decision: AIChatAgent.** Pi would probably also meet the purpose. AIChatAgent is chosen for three reasons: a provider is
reached directly through its AI SDK provider without Gateway, MCP integration already exists, and valibot with the AI SDK
keeps the whole repository on one set of libraries.

Costs accepted:

- **No interruption.** A new question cannot interrupt a running turn. The wait is bounded by folding analyses into the
  latest head, running a waiting question before the next analysis, and showing the waiting state in the UI. Pending
  analyses never delay a waiting question, but a question can still wait behind the current turn, earlier queued
  questions and, for a local-owned session, an absent local agent.
- **Compaction is ours to write.** It is accepted because the prototype's check showed it keeps earlier decisions
  across repeated compaction (see [spikes.md](spikes.md)).
- **Experimental status is unknown.** Recovery is not treated as exactly-once; job commits are idempotent instead.

If a provider that cannot be reached through an AI SDK provider is needed, or compaction fails the adoption test at a
realistic context length, this comparison is the place to return to.
